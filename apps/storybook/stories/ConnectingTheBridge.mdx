# Connecting the Bridge (Claude Code ↔ Figma)

The **S2A Toolkit** plugin can connect to **Claude Code** (or any MCP client) so an
AI assistant can read and drive your Figma file — the same `figma_execute`
workflow the design-infra team uses. This page gets you connected in three steps.

The Bridge is **optional**. The toolkit's other features — component docs,
annotations, variant filter, token release — work without it.

## How it fits together

The toolkit plugin (in Figma) is the **Bridge client**. It connects over a local
WebSocket to a small **MCP server** running on your machine, which your MCP client
launches. We ship that server as a one-command launcher, **`@adobecom/s2a-toolkit-bridge`**
(a pinned, known-good `figma-console-mcp`).

```
Claude Code  ⇄  @adobecom/s2a-toolkit-bridge  ⇄  S2A Toolkit plugin  ⇄  your Figma file
              (MCP / stdio)     (ws://localhost:9223–9232)
```

## You need

<ul>
  <li><strong>Figma Desktop</strong> — the web app can't run the Bridge.</li>
  <li>The <strong>S2A Toolkit</strong> plugin, installed from <strong>Adobe Enterprise</strong> in Figma.</li>
  <li>An <strong>MCP client</strong> — Claude Code, Cursor, etc.</li>
  <li>A <strong>Figma personal access token</strong> (starts with <code>figd_</code>) — <a href="https://help.figma.com/hc/en-us/articles/8085703771159-Manage-personal-access-tokens" target="_blank" rel="noreferrer">create one here</a>.</li>
</ul>

## Step 1 — Point npm at GitHub Packages (once)

In your `~/.npmrc`:

```ini
@adobecom:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

Set `GITHUB_TOKEN` in your environment (a `read:packages` token, authorized for the
`adobecom` org).

## Step 2 — Add the Bridge server to your MCP client

**Claude Code:**

```bash
claude mcp add s2a-toolkit-bridge -s user \
  -e FIGMA_ACCESS_TOKEN=figd_YOUR_TOKEN_HERE \
  -- npx -y @adobecom/s2a-toolkit-bridge
```

**By hand** (Claude Code `.mcp.json`, Cursor `.cursor/mcp.json`, …):

```json
{
  "mcpServers": {
    "s2a-toolkit-bridge": {
      "command": "npx",
      "args": ["-y", "@adobecom/s2a-toolkit-bridge"],
      "env": { "FIGMA_ACCESS_TOKEN": "figd_YOUR_TOKEN_HERE" }
    }
  }
}
```

Your MCP client launches the server on demand — nothing to start or manage yourself.

## Step 3 — Open the Bridge in Figma

In **Figma Desktop**, open the **S2A Toolkit** plugin → **Bridge** tab. It scans
ports `9223–9232` and connects to the running server. Claude Code can now read and
drive your file.

## Troubleshooting

<ul>
  <li><strong>Bridge tab won't connect</strong> — make sure your MCP client has actually started the server (open Claude Code and use any Figma tool once), and that you're in <strong>Figma Desktop</strong>, not the browser.</li>
  <li><strong>Auth errors</strong> — the <code>FIGMA_ACCESS_TOKEN</code> must be a valid <code>figd_…</code> token; regenerate if unsure.</li>
  <li><strong>Port already in use</strong> — the server falls back across <code>9223–9232</code>; the toolkit scans the same range, so a fallback port still connects.</li>
</ul>
