HTTP Bridge Endpoint — What to Add

POST http://localhost:9240/figma
// Body: { method: string, params: object, timeout?: number }
→ routes to sendCommand(method, params, timeout)
→ returns { result } or { error }

GET http://localhost:9240/status
// Returns { connected: bool, port: number } — used by extension to check if plugin is open

This is a one-time addition to the existing MCP server. All existing functionality (stdio MCP, WebSocket to Figma) is unchanged. The HTTP server just adds a new entry point that routes through the same sendCommand() already in use.

Side Panel Fallback Mode (for strict-CSP sites)

When iframe fails:
  1. Extension shows error card: "This site blocks iframe embedding"
  2. User clicks "Open in Side Panel mode" button
  3. Extension opens the URL in a real Chrome tab
  4. Chrome Side Panel opens on right with Claude chat (same conversation, same context)
  5. Left rail becomes a content-script overlay injected into the real page
  6. All extraction tools work identically — DOM access via content script, not iframe
  7. Preview tab and Save to folder outputs unchanged
  8. Figma bridge unchanged

The Side Panel fallback is full-featured — not a degraded mode. The only difference is that the page renders in a real tab instead of inside the 3-column shell. When the user exits the site, they return to the extension tab.
